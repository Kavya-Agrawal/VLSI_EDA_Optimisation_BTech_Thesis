PV-Evolve

Path-Verified Evolution of OpenROAD Physical Design Code

Adapting Self-Evolved ABC for Physical Design with Multi-Domain Correctness Contracts

Motivation: Why ABC's Approach Doesn't Transfer Directly

The Self-Evolved ABC framework (2604.15082v1) achieves 8.3% QoR improvement by evolving ABC's logic synthesis codebase using multi-agent LLM code evolution. Its correctness guarantee is Combinational Equivalence Checking (CEC) — a single logical check that the evolved code produces functionally identical outputs.

The Gap: Physical design code evolution requires correctness across 6 orthogonal domains (structural, geometric, temporal, electrical, formal, functional). A code change that preserves logical equivalence can still break DRC, degrade timing, or violate electrical constraints. No existing work formalizes this multi-domain requirement.

Why Physical Design Needs 6 Layers (Not Just CEC)

ABC evolves logic synthesis code where correctness = logical equivalence. OpenROAD evolves physical design code where correctness spans 6 orthogonal domains. Consider: a Resizer code change might improve timing (L4 passes) and preserve logic (L6 passes) but introduce an antenna violation from changed wire lengths (L5 fails) — invisible to CEC, caught only by PVCC.

Novel Contribution 2: Timing-Path-Guided Mutation Novel

Current evolution uses blind mutation — random operator selection with no awareness of which code blocks affect critical timing paths. TPGM closes this loop.

SSPE: Segmented Semantic Program Evolution

Evolved C++ code is represented as audited blocks in a binary segment tree with a semantic relation graph. Mutation operators: replace, insert, delete, swap, segment_reverse, segment_duplicate, graph_swap, graph_insert_bridge. TPGM biases operator target selection within this structure.
