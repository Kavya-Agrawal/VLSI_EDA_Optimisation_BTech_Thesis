- **Window and DP:** For each ranked bottleneck driver, I build a window of up to 4 consecutive driver stages on the current worst path to that driver's worst endpoint. Each stage's candidates are the current master plus swappable masters with no weaker drive resistance on either edge. The DP picks one master per stage, using each stage's load and a side-load penalty.
- **Applying the move:** The result is applied as one compound move inside `committer_.beginJournal()`. It is kept only if it passes the existing WNS floor and 0.5 ps TNS gain check. Otherwise the journal is restored and the stock attempts run as before.
- **Counters:** It prints `window_dp_examined`, `_with_gain`, `window_joint_changed_vs_greedy`, `_stages_changed`, `_trials`, `_kept`, `_rejected_wns` and `_rejected_tns`, each as `RSZ_EVOLVE <name> fired=<n>`.
- **Concern:** The delay estimate ignores slew propagation, so wire-dominated stages may be mis-estimated.
